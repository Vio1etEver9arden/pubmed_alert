# 📚 PubMed Alert

[English](README.md) · **中文** · [日本語](README.ja.md)

按关键词 / 期刊 / 作者订阅 PubMed 新文献，定期（或实时）通过邮件推送给你，并标注官方 JCR 影响因子和分区作为参考。

> 定位：小范围自用/分享，本地运行，不含用户注册系统。以后要部署到你自己的服务器上，直接把整个文件夹搬过去、装依赖即可，代码不需要改。

---

## 功能

- 🔍 按关键词、期刊、作者组合检索 PubMed 新文献（也支持直接写高级检索式）
- 📧 通过你自己的邮箱账号发送邮件通知（支持 Gmail / QQ邮箱 / 163邮箱 / Outlook 等，或任意其他 SMTP 邮箱）
- ⏱ 每个订阅可单独设置频率：有新文献立即发送 / 每天 / 每3天 / 每周汇总
- 🏷 邮件中标注官方 JCR 影响因子和分区（Q1–Q4）作为影响力参考
- 🌐 简单的网页界面管理订阅（增删改查、立即检查、查看已发现的文献）
- 🌏 界面支持中文 / English / 日本語，右上角随时切换
- ⚙️ 发件邮箱、NCBI API Key 都在网页「设置」页面配置，密码加密存储，不需要手动编辑配置文件

## 快速开始

### 方式一：用 Python 自己运行

```bash
cd pubmed_alert
pip install -r requirements.txt
python run.py
```

然后浏览器打开 **http://127.0.0.1:8000**。第一次运行会自动创建本地数据库。

### 方式二：使用别人打包好的程序（不用装 Python）

如果有人给了你一个 `PubMedAlert.exe`（Windows）或 `PubMedAlert`（Mac），直接双击运行即可，
浏览器会自动打开。如果你是要打包发给别人的那个人，看下面「打包给不会用 Python 的人」一节。

### 配置发件邮箱

打开网页后，点击顶部导航的「设置」，在「邮箱服务商」下拉框里选择你用的邮箱（Gmail / QQ邮箱 /
163邮箱 / Outlook，或选「自定义」手动填 SMTP 服务器），填入邮箱地址和密码/授权码（见下方），
保存后可以用「发送测试邮件」按钮验证配置是否正确。

## 邮箱配置指南

⚠️ 密码保存后会加密存进本地数据库。不要分享 `data/subscriptions.db` 或 `data/app_secret.key`
这两个文件给别人，也永远不要把密码粘贴到聊天记录或截图里。

### Gmail

Gmail 不允许直接用你的登录密码通过第三方程序发送邮件，需要生成一个专用的**应用专用密码**。

1. 打开 [myaccount.google.com/security](https://myaccount.google.com/security)，确保已经开启
   「两步验证」（应用专用密码功能必须先开启两步验证才可用）。
2. 打开 [myaccount.google.com/apppasswords](https://myaccount.google.com/apppasswords)，创建一
   个新的应用专用密码（名称随便填，比如 "PubMed Alert"）。
3. 复制生成的 16 位密码，粘贴到网页「设置」页面「密码 / 授权码」一栏，连同 Gmail 地址一起保存。

### QQ 邮箱 / 163 邮箱

这两家都不允许用登录密码发信，需要在邮箱网页版里单独开启 SMTP 服务并生成一个**客户端授权码**，
把这个授权码当密码填进「密码 / 授权码」一栏（不是你的登录密码）。

- QQ 邮箱：登录网页版 → 设置 → 账户 → 开启「POP3/SMTP服务」→ 按提示发短信验证生成授权码。
- 163 邮箱：登录网页版 → 设置 → POP3/SMTP/IMAP → 开启服务 → 生成客户端授权密码。

网页「设置」页面选择对应的邮箱服务商后，SMTP 服务器地址和端口会自动填好，你只需要填邮箱地址
和这个授权码即可。

### Outlook / Microsoft 365

用你的 Outlook 登录密码即可（如果账号开启了双重验证，则需要在
[account.microsoft.com/security](https://account.microsoft.com/security) 里生成一个应用密码）。

### 其他邮箱服务商

在「设置」页面的「邮箱服务商」下拉框里选择「自定义」，然后手动填写该邮箱服务商的 SMTP 服务器
地址、端口，并根据其文档判断是否需要勾选「使用 SSL」：一般 465 端口用 SSL，587 端口用
STARTTLS（不勾选）。具体信息请查阅该邮箱服务商官方的 SMTP 设置说明。

## 影响因子 / JCR 分区数据

PubMed 本身不提供影响因子或分区数据。这个项目自带一份预先解析好的官方 **Journal Citation
Reports (JCR)** 数据快照（`data/jcr_cache.csv`），会自动使用，不需要额外配置。

## 使用说明

1. 打开首页，点击「新建订阅」。
2. 填写关键词 / 期刊 / 作者（每行一个，任意组合，留空即不作为筛选条件）。想写复杂检索式的话，
   用「高级：自定义 PubMed 检索式」这一栏，会覆盖上面三项。
3. 填写收件邮箱和发送频率，保存。
4. 点击「立即检查」可以马上跑一次检索，在「查看文献」里能看到抓到的结果，不需要等待定时任务。

新建订阅第一次检查时，会取近 **5 年**内最相关的 **10 篇**文献作为"入门文献"；之后每次检查只
发送新发表的文献。

**发送频率说明：**
- **立即发送**：发现新文献就立刻发一封邮件。
- **每天 / 每3天 / 每周**：把这段时间内新发现的文献攒到一起，凑够周期后一次性发送汇总邮件；
  期间没有新文献则不发送。

**关掉浏览器页面 ≠ 关掉程序**：程序需要一直在后台跑着，才能按你设置的频率定时检查、按时发信；
只关浏览器标签页不会停掉它，这是正常的，不用管。真的想彻底停掉的话：打包版 App 在 Dock 里
`Cmd+Q` 或右键选「退出」；用 `python run.py` 跑的话回到对应的终端窗口按 `Ctrl+C`。不管停没停、
点了几次图标，重新打开都是安全的——如果发现已经在后台跑着，会直接把浏览器带过去，不会报错或
起第二份。

## 打包给不会用 Python 的人

如果对方不装/不会用 Python，可以用 `packaging/` 里的脚本把整个程序打包成一个独立的可执行文件；
对方拿到文件后直接双击运行，浏览器会自动打开，不需要装任何东西。**每个人独立运行自己的一份**，
各自有自己的数据库和发件邮箱配置。

打包必须在目标系统上进行（PyInstaller 不能跨平台编译）：

```powershell
# 在 Windows 上运行，产出 dist\windows\PubMedAlert.exe
powershell -ExecutionPolicy Bypass -File packaging\build_windows.ps1
```

```bash
# 在 Mac 上运行，产出 dist/mac/PubMedAlert.app 和 dist/mac/PubMedAlert.zip
chmod +x packaging/build_mac.sh
./packaging/build_mac.sh
```

**Windows**：把生成的 `PubMedAlert.exe` 发过去就行，请对方先放进一个新建的空文件夹里再双击
（不要在下载目录或压缩包里直接运行）——运行后会在旁边生成 `data/` 文件夹存数据库。

**Mac**：把生成的 `PubMedAlert.zip` 发过去（不要发未压缩的 `.app`，压缩包才能完整保留内部结
构）。对方操作：解压 → 右键点 `PubMedAlert.app` → 选「打开」→ 弹出的安全提示里再次确认「打
开」。这一步之后就是一个普通的 Mac App，正常双击图标即可，双击后**不会弹出终端窗口**，浏览器
会自动打开。之所以第一次不能直接双击，是因为这个 App 没有花 Apple 开发者账号（$99/年）去做官方
签名，macOS Gatekeeper 会拦截未签名的 App；构建脚本已经做了本机自签名，避免了 Apple Silicon
上更麻烦的「已损坏，无法打开」报错，只剩这一次「右键打开」是绕不过去的。

每个接收者需要自己配置发件邮箱的密码/授权码，以及（可选）自己的 JCR 数据——参考上面的对应章节。
