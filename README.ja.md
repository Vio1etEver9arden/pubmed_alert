# 📚 PubMed Alert

[English](README.md) · [中文](README.zh.md) · **日本語**

キーワード / 雑誌 / 著者で PubMed の新着論文を購読し、定期的に（またはリアルタイムで）メール
でお知らせします。公式の JCR インパクトファクターとクォータイルも参考情報として表示されます。

> 想定用途：個人利用または少人数での利用、ローカル実行、ユーザー登録機能なし。将来自分のサー
> バーに移す場合も、フォルダごとコピーして依存関係をインストールするだけで、コードの変更は不
> 要です。

---

## 機能

- 🔍 キーワード・雑誌・著者を組み合わせて PubMed の新着論文を検索（高度な検索式を直接記述する
  ことも可能）
- 📧 自分のメールアカウントから通知を送信（Gmail / QQメール / 163メール / Outlook などに対応、任意の他の SMTP メールも利用可能）
- ⏱ 購読ごとに送信頻度を個別設定：新着があれば即時送信 / 毎日 / 3日ごと / 毎週まとめて送信
- 🏷 メールには公式の JCR インパクトファクターとクォータイル（Q1〜Q4）を表示
- 🌐 購読管理用のシンプルな Web UI（作成・編集・削除、今すぐチェック、文献の閲覧）
- 🌏 画面表示は 英語 / 中文 / 日本語 に対応、右上でいつでも切り替え可能
- ⚙️ 送信元メールアカウントと NCBI API キーは Web の「設定」画面で設定（パスワードは暗号化して
  保存）。設定ファイルを手で編集する必要はありません

## クイックスタート

### 方法1：Python で自分で動かす

```bash
cd pubmed_alert
pip install -r requirements.txt
python run.py
```

ブラウザで **http://127.0.0.1:8000** を開いてください。初回起動時にローカルデータベースが自
動作成されます。

### 方法2：誰かがビルドしたプログラムを使う（Python 不要）

`PubMedAlert.exe`（Windows）や `PubMedAlert`（Mac）を誰かから受け取った場合は、ダブルクリッ
クするだけで起動し、ブラウザが自動的に開きます。自分がビルドして配布する側の場合は、下の「Py
thon を使わない人への配布」を参照してください。

### 送信元メールアカウントの設定

アプリを開き、上部ナビゲーションの「設定」をクリックして、「メールサービス」のプルダウンから
使っているサービス（Gmail / QQメール / 163メール / Outlook、または SMTP を手動入力する「カス
タム」）を選び、メールアドレスとパスワード/認証コード（下記参照）を入力して保存してください。
「テストメール送信」ボタンで動作確認できます。

## メール設定ガイド

⚠️ 保存されたパスワードはローカルデータベースに暗号化して保存されます。`data/subscriptions.
db` と `data/app_secret.key` は他人と共有しないでください。また、パスワードをチャットのログ
やスクリーンショットに貼り付けないでください。

### Gmail

Gmail は通常のログインパスワードでのプログラムからの送信を許可していないため、専用の
**アプリパスワード** を発行する必要があります。

1. [myaccount.google.com/security](https://myaccount.google.com/security) を開き、「2段階認
   証プロセス」が有効になっていることを確認してください（アプリパスワードには2段階認証が必須
   です）。
2. [myaccount.google.com/apppasswords](https://myaccount.google.com/apppasswords) を開き、新
   しいアプリパスワードを作成します（名前は任意、例："PubMed Alert"）。
3. 生成された16桁のパスワードをコピーし、Web の「設定」画面の「パスワード / 認証コード」欄に、
   Gmail アドレスとあわせて貼り付けて保存します。

### QQメール / 163メール

どちらもログインパスワードでの送信は許可されていません。Web メール側の設定で SMTP サービスを
有効にし、**クライアント認証コード** を発行してから、それをログインパスワードの代わりに「パ
スワード / 認証コード」欄に入力してください。

- QQメール：Web メールにログイン → 設定 → アカウント → 「POP3/SMTPサービス」を有効化 → SMS
  認証で認証コードを発行。
- 163メール：Web メールにログイン → 設定 → POP3/SMTP/IMAP → サービスを有効化 → クライアント
  認証パスワードを発行。

「設定」画面で該当するメールサービスを選ぶと、SMTPサーバーとポートは自動的に入力されるので、
メールアドレスとこの認証コードを入力するだけで済みます。

### Outlook / Microsoft 365

通常の Outlook ログインパスワードで動作します（2段階認証が有効な場合は
[account.microsoft.com/security](https://account.microsoft.com/security) でアプリパスワードを
発行してください）。

### その他のメールサービス

「設定」画面の「メールサービス」プルダウンで「カスタム」を選び、そのサービスの SMTP サーバー
アドレスとポートを手動で入力し、そのドキュメントに従って「SSLを使用」のチェックを判断してくだ
さい。一般的に465番ポートはSSL、587番ポートはSTARTTLS（チェックなし）です。正確な値はそのメー
ルサービスのSMTP設定ドキュメントを確認してください。

## インパクトファクター / JCR クォータイル（任意）

PubMed 自体にはインパクトファクターやクォータイルのデータはありません。公式の
**Journal Citation Reports (JCR)** は Clarivate 社の有料データで、通常は所属機関の購読を通じ
てアクセスします。このプロジェクトはこの有料データを不正に取得・回避する処理は一切行いません
——自分自身のアクセス権限が必要です。

1. 所属機関の Web of Science / JCR アクセス権限で、その年の "Journal Impact Factor" レポート
   を PDF としてエクスポートします。
2. その PDF をこのプロジェクトの `data/` フォルダに置きます。
3. 次を実行します：
   ```bash
   pip install pdfplumber
   python scripts/parse_jcr_pdf.py "data/JCR Journal Impact Factor 2026.pdf"
   ```
4. プログラムを再起動すると反映されます（ホーム画面上部の黄色い通知が消えます）。

この手順を省略しても他の機能には影響しません。メールにインパクトファクター/クォータイルの表
示が付かないだけです。JCR が更新される年1回のタイミングで再エクスポートすることをおすすめし
ます。これは各自で行う作業です——それぞれが自分のアクセス権限で自分のキャッシュファイルを生成
します。共有したり Git にコミットしたりすることはありません。

## 使い方

1. ホーム画面を開き、「新規購読」をクリックします。
2. キーワード / 雑誌 / 著者を入力します（1行に1つ、任意の組み合わせ、空欄でその条件をスキッ
   プ）。複雑な検索式を書きたい場合は「上級者向け：PubMed検索式を直接指定」欄を使うと、上の3
   項目より優先されます。
3. 宛先メールアドレスと送信頻度を入力して保存します。
4. 「今すぐチェック」をクリックするとすぐに検索が実行され、「文献を見る」で結果を確認できま
   す（定期実行を待つ必要はありません）。

新規購読の初回チェックでは、過去 **5年間** で最も関連性の高い **10件** を「入門文献」として送
信します。以降のチェックでは新しく発表された文献のみを送信します。

**送信頻度について：**
- **新着があれば即時送信**：新しい文献が見つかり次第すぐにメールを送信します。
- **毎日 / 3日ごと / 毎週まとめて送信**：その期間内に見つかった新着文献をまとめて、周期が来
  たタイミングで1通のメールを送信します。新着がなければメールは送信されません。

**ブラウザのタブを閉じる ≠ アプリを終了する**：設定した頻度で検索・送信を続けるため、バックグ
ラウンドで動き続ける必要があります。ブラウザのタブを閉じるだけでは止まりません——これは正常な
動作なので気にしないでください。本当に止めたい場合：パッケージ版アプリは `Cmd+Q` または Dock
アイコンを右クリックして「終了」、`python run.py` で動かしている場合はそのターミナルに戻って
`Ctrl+C`。いずれの場合も、再度開くのは常に安全です——すでにバックグラウンドで動いていれば、エ
ラーになったり二重に起動したりせず、そのままブラウザを開き直すだけです。

## Python を使わない人への配布

Python を持っていない、または使いたくない相手には、`packaging/` 内のスクリプトを使ってアプリ
を単一の実行ファイルにパッケージ化できます。相手はファイルをダブルクリックするだけで起動し、
ブラウザが自動的に開きます——他に何もインストールする必要はありません。**各自が自分専用のコピ
ーを独立して実行**し、それぞれが自分のデータベースと送信元メールアカウント設定を持ちます。

ビルドは対象の OS 上で行う必要があります（PyInstaller はクロスコンパイルできません）：

```powershell
# Windows 上で実行、dist\windows\PubMedAlert.exe が生成されます
powershell -ExecutionPolicy Bypass -File packaging\build_windows.ps1
```

```bash
# Mac 上で実行、dist/mac/PubMedAlert.app と dist/mac/PubMedAlert.zip が生成されます
chmod +x packaging/build_mac.sh
./packaging/build_mac.sh
```

**Windows**：生成された `PubMedAlert.exe` だけを送ればOKです。相手には、ダウンロードフォルダ
や zip の中で直接実行せず、新しく作った空のフォルダに入れてからダブルクリックしてもらってくだ
さい（実行すると隣に `data/` フォルダが作られ、データベースが保存されます）。

**Mac**：生成された `PubMedAlert.zip` を送ってください（解凍前の `.app` ではなく——zip にする
ことで内部構造が壊れずに届きます）。相手の操作：解凍 →`PubMedAlert.app` を右クリック →「開
く」→ セキュリティ確認ダイアログでもう一度「開く」。これで普通の Mac アプリになり、以降は普通
にダブルクリックでき、**ターミナルウィンドウは表示されず**、ブラウザも自動的に開きます。この
初回の右クリックは、有料の Apple Developer 署名（年間$99）なしでは避けられません。ビルドスク
リプトはローカルでの自己署名（アドホック署名）を行っており、これにより Apple Silicon で未署名
アプリによく起きる、より分かりにくい「アプリは壊れている」エラーは回避できます。

各受信者は自分自身の送信元メールアカウントのパスワード/認証コードと、（任意で）自分自身の JCR データを設定する必要
があります——上記の該当セクションを参照してください。
